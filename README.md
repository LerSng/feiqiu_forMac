# 飞秋 Mac

基于 SwiftUI 的 macOS 局域网即时通讯客户端，面向飞秋 2013 Windows 版提供用户发现、在线状态同步和文字消息互通能力。

项目采用分层架构，将界面状态、业务编排、协议通信、数据持久化和系统通知分别隔离，便于持续扩展协议兼容能力和聊天功能。

> 当前版本：`0.1.1`（Build `2`）

## 项目概览

| 项目 | 说明 |
| --- | --- |
| 支持平台 | macOS 14.0 及以上 |
| 用户界面 | SwiftUI |
| 开发语言 | Swift 5 |
| 网络协议 | 飞秋/IP Messenger 兼容报文 |
| 通信端口 | UDP/TCP `2425` |
| 本地存储 | SQLite |
| 兼容目标 | 飞秋 2013 Windows 版的局域网文字与图片通信 |
| 数据范围 | 仅局域网直连，不依赖云端服务器 |

## 功能特性

### 局域网通信

- 通过 UDP `2425` 广播上线、回复上线、刷新用户列表和发送离线通知。
- 支持点对点文字消息及消息接收回执。
- 支持飞秋内嵌图片：正文图片标记 + UDP `0x2000C0` 分片，逐片回复 `0xC1`；发送端支持回执确认和有限重试。
- 保留普通图片文件附件的 TCP `2425` 下载能力。
- 支持在消息输入框使用 `⌘V` 粘贴文本或图片；粘贴的图片会先进入待发送区，可移除后再发送。
- 聊天图片支持右键“复制图片”，复制后可直接回到输入框粘贴发送。
- 支持飞秋扩展版本头 `1_lbt6_0#...`，可被飞秋 2013 Windows 版识别。
- 支持 GB18030/GBK 兼容编码，降低中文消息在 Windows 版中出现乱码的概率。
- 支持 IPv4 局域网内的 UDP 消息接收和 TCP `2425` 监听。

### 聊天体验

- 联系人搜索、在线状态、最近会话和未读消息数量展示。
- 消息使用自适应宽度气泡显示，区分发送方和接收方。
- 支持消息时间展示，点击日期可查看完整的年月日、时分秒。
- 支持消息进入动画，包括“两侧汇聚”、淡入、上浮、缩放、立即显示和随机模式。
- 支持 macOS 系统通知；点击通知后可直接进入对应联系人或群聊会话。
- 支持飞秋兼容表情的发送和解析：
  - `/:)` ↔ `🙂`（飞秋第 1 个内置表情，按 `feiqiu-README.md` 实测规则处理）
  - `/<rotate>` ↔ `🔄`
  - `/:baoquan` ↔ `✊`
  - `/:love` ↔ `❤️`
  - 保留旧版本 `/:fd`、`/:cajole`、`/:o` 兼容解析
- 图片统一保存到 `~/Documents/飞秋 Mac/Images`，聊天记录只保存图片元数据和本地路径。

### 群聊

- 支持在 Mac 端创建、编辑和删除群聊。
- 支持从在线联系人中选择群成员，并持久化群聊成员关系。
- Mac 作为群聊中继节点：Mac 发送的群消息会转发给所有在线成员，成员发送给 Mac 的消息也会中继给同群其他在线成员。
- Windows 成员收到中继消息时，会在普通飞秋消息中看到 `【飞秋群聊：群名】发送人：消息` 标记，从而识别群聊名称和原始发送人。
- 群聊消息、未读数量和群聊配置均纳入统一的本地历史记录体系。

### 历史记录与性能

- 聊天记录统一保存到 SQLite，不因重新编译或重新启动应用而丢失。
- 联系人、群聊、成员关系、会话摘要和消息记录分类存储。
- 数据库访问使用后台串行队列，避免阻塞 SwiftUI 主线程。
- 会话首次进入只加载最近一页消息，向上滚动时再分页加载更早记录。
- 支持从早期版本的 `ChatHistory.json` 迁移到 SQLite。
- 提供网络诊断日志，便于定位端口、编码、广播和回执问题。

| TCP 数据连接 | 支持 | 普通图片文件附件通过 TCP `2425` 请求下载 |
| 内嵌图片 | 已实现，待 Windows 双机验证 | 关联正文图片 ID，UDP 分片重组、逐片确认、去重和有限重试 |

| 剪贴板 | 支持 | 文本按光标位置粘贴；PNG、TIFF、JPEG、HEIC 和 Finder 图片文件可粘贴为待发送图片 |
| 其他文件、语音 | 暂不支持 | 非图片文件会被忽略，不会写入聊天记录 |

### 群聊兼容边界

飞秋 2013 Windows 版没有可供本项目直接使用的原生群聊报文，因此当前采用“Mac 中继群聊”方案：Mac 必须保持在线，成员之间的消息先发送到 Mac，再由 Mac 转发给其他群成员。Windows 端收到的底层仍是普通飞秋点对点消息，但消息正文带有群名和原始发送人标记，因此所有在线成员可以看到同一群聊内容。

由于传统飞秋消息本身不携带群组 ID，群成员发给 Mac 的普通消息会被视为群消息并转发给其所在群组的其他成员。若需要私聊，请使用单聊会话。Mac 下线后，群聊中继会暂时停止，成员之间不会自动直连。

## 技术架构

项目遵循单向依赖原则：

```text
View → ViewModel → Repository → Service → Model
```

- `View`：只负责界面展示、用户交互和局部 UI 状态，不直接访问网络或数据库。
- `ViewModel`：管理界面可观察状态、会话切换、未读数、加载状态和动画选择，不直接操作底层存储或 Socket。
- `Repository`：组合网络、历史记录和通知服务，完成业务编排、数据转换、会话归并和消息路由。
- `Service`：提供网络、SQLite、UserDefaults 和 macOS 通知等底层能力，不承载页面业务逻辑。
- `Model`：定义联系人、消息、群聊、身份信息及飞秋协议报文等领域数据结构。

### 目录结构

```text
FeiQMac/
├── Models/          # 联系人、消息、群聊、身份和领域模型
├── Protocol/        # 飞秋报文格式、命令码、编码和表情转换
├── Network/         # UDP/TCP Socket 和网络生命周期管理
├── Persistence/     # SQLite 数据库、表结构、分页查询和旧数据迁移
├── Services/        # 历史记录、通知和用户设置等底层服务
├── Repositories/    # 网络、存储和通知的业务组合层
├── ViewModels/      # SwiftUI 页面状态和用户交互逻辑
├── Views/           # 主界面、侧栏、聊天页、设置、群聊和公共组件
└── Resources/       # Info.plist 和应用资源
```

## 环境要求

- macOS 14.0+
- Xcode 15 或更高版本
- Swift 5
- 运行设备与 Windows 飞秋客户端位于同一个局域网广播域

## 构建与运行

### 使用 Xcode

1. 使用 Xcode 打开 `FeiQMac.xcodeproj`。
2. 选择 `FeiQMac` Scheme。
3. 选择本机 Mac 作为运行目标并启动。

### 使用命令行

```sh
xcodebuild \
  -project FeiQMac.xcodeproj \
  -scheme FeiQMac \
  -configuration Debug \
  -sdk macosx \
  CODE_SIGNING_ALLOWED=NO \
  build
```

建议启动构建生成的 `.app`。不要直接运行 `Contents/MacOS/FeiQMac`，否则 macOS 可能无法按照应用身份正确处理本地网络权限和通知能力。

## 首次运行配置

首次启动时需要在 macOS 中允许以下权限：

1. 打开“系统设置 → 隐私与安全性 → 本地网络”，允许“飞秋 Mac”访问本地网络。
2. 如果系统防火墙拦截入站连接，在“系统设置 → 网络 → 防火墙 → 选项”中允许“飞秋 Mac”接收传入连接。
3. 如需桌面提醒，在通知设置中允许“飞秋 Mac”发送通知。

应用设置页可以修改昵称、主机名、分组以及聊天记录进入动画。保存身份信息后，应用会重新广播上线信息。

## 联调说明

### Windows 端看不到 Mac

- 确认两台设备连接到同一个局域网和同一个广播域。
- 确认 macOS 已授权本地网络访问。
- 确认 Windows 防火墙放行 UDP/TCP `2425`。
- 检查网络日志中是否出现“已监听 UDP/TCP 2425，正在广播上线信息”。
- 部分企业 Wi-Fi、访客网络或 VLAN 会隔离广播，此时即使 IP 可达，也可能无法发现用户。

### 中文显示乱码

飞秋 2013 Windows 版通常按 GB18030/GBK 解析传统消息报文。项目对发送给旧版 Windows 的消息使用兼容编码；如果对方是修改版客户端，仍可能因其编码策略不同而出现差异。请优先使用网络日志确认实际收发路径和报文解析结果。

### 消息发送失败

发送失败通常与以下因素有关：

- 对方已经下线或 IP 地址发生变化；
- UDP `2425` 被防火墙或网络隔离策略拦截；
- 两台设备不在同一广播域；
- 对方客户端未监听标准飞秋端口；
- 目标客户端对飞秋扩展版本或编码存在兼容差异。

### 聊天记录位置

默认存储路径为：

```text
~/Documents/飞秋 Mac/ChatHistory.sqlite
```

图片附件默认存储在：

```text
~/Documents/飞秋 Mac/Images
```

同目录下的 `ChatHistory.json` 用于旧版本数据迁移。数据库文件属于本地用户数据，删除或移动前请先退出应用并做好备份。

### 图片收发失败

- 确认 Windows 飞秋和 Mac 位于同一局域网，并且双方防火墙放行 TCP/UDP `2425`。
- 飞秋“粘贴图片/截图”走 UDP 分片；以“文件”发送的图片才走 TCP 下载。日志中的 `0x2000C0` 是图片数据，`0xC1` 是分片确认。
- 正文中 `/~#>八位ID<B~` 与图片分片关联，分片可以乱序或重复到达。接收超时后显示失败提示，不再把图片 ID 当作聊天文字。
- 发送图片统一转换为 JPEG，最长边限制为 4096 像素、质量 0.9；GIF 发送静态首帧，透明度不保留。单张源文件/传输图片上限为 20 MB。
- 接收支持 JPEG 等可由 ImageIO 解码的图像及飞秋未压缩 DIB 位图；不支持的压缩变体会记录解码错误。
- 当前只处理常见图片扩展名：`jpg`、`jpeg`、`png`、`gif`、`bmp`、`tif`、`tiff`、`webp`、`heic`、`heif`。
- 飞秋不同版本的文件附件实现可能存在差异，若无法接收，请保留应用“网络日志”中的附件元数据和 TCP 错误信息用于兼容性排查。
- 剪贴板图片会先转换为 JPEG 保存到 `~/Documents/飞秋 Mac/Images`，点击发送后才进入飞秋内嵌图片分片流程；转换期间发送按钮会暂时禁用。

旧版本只存下图片占位码、没有保存图片字节的历史消息无法自动还原，需要对方重新发送。

协议回归检查位于 `Tests/InlineImageProtocolChecks.swift`，覆盖 Windows 报文格式、二进制尾部、乱序重组、去重、跨好友 ID 隔离和丢包重试。协议依据参考 [HIM](https://github.com/alakenda/HIM) 的截图协议及 [feiq-android](https://github.com/zyqg/feiq-android) 的抓包说明；实际 Windows 飞秋 2013 显示效果仍需双机联调验证。

## 数据与隐私

- 应用不依赖中心服务器，消息默认只通过局域网 UDP 直接发送。
- 聊天记录保存在本机“文稿/飞秋 Mac”目录，不会自动上传云端。
- 当前飞秋兼容报文未提供端到端加密，局域网内具备抓包能力的设备可能读取消息内容。
- 请不要在未确认网络可信的环境中传输敏感信息。
