# 飞秋 Mac

基于 SwiftUI 的 macOS 局域网即时通讯客户端，兼容飞秋 / IP Messenger 报文，面向 **飞秋 2013 Windows 版**提供文字、图片和普通文件通信，并扩展本地历史搜索、记录导入导出、会话管理与数据库维护能力。

当前版本：`0.1.1`（Build `2`） · macOS `14.0+` · Swift `5` · SQLite · UDP/TCP `2425`

> 本机功能与协议回归已覆盖下述主要能力，但不等同于完成 Windows 双机互通、真实通知声音或发行包验收。项目不依赖中心服务器，当前协议不提供端到端加密；请在可信局域网内使用。

## 快速开始

### 环境要求

- macOS 14.0 或更高版本，Xcode 15 或更高版本。
- Mac 与 Windows 飞秋客户端位于可互通的 IPv4 局域网；广播发现通常要求同一广播域。
- 防火墙允许飞秋程序的 UDP/TCP `2425` 通信。

### 构建与运行

1. 使用 Xcode 打开 `FeiQMac.xcodeproj`，选择 `FeiQMac` Scheme 和本机 Mac。
2. 检查 Target 的签名设置及 **Build Phases 中的签名 / DMG 脚本**，再运行应用。
3. 本地调试可停用该打包阶段；发布时再配置实际产物名称、Developer ID 证书和 `create-dmg`。

项目现有打包脚本包含证书占位值、固定的 `feiqiu_forMac.app` 路径，并向桌面输出 DMG。未配置时可能在应用编译后失败；仅传入 `CODE_SIGNING_ALLOWED=NO` **不会跳过脚本内部的 `codesign`**。本次功能开发未调整该脚本。

完成上述配置后，也可通过命令行构建：

```sh
xcodebuild \
  -project FeiQMac.xcodeproj \
  -scheme FeiQMac \
  -configuration Debug \
  -sdk macosx \
  CODE_SIGNING_ALLOWED=NO \
  build
```

请启动构建生成的 `.app`，不要直接运行 `Contents/MacOS/FeiQMac`，以便 macOS 按应用身份处理本地网络和通知权限。只检查代码与行为时，可运行[回归脚本](#开发与验证)，无需执行签名 / DMG 阶段。

### 首次配置

- 按系统提示允许本地网络访问，并在防火墙中允许入站连接。
- 需要桌面提醒时，允许应用发送通知；截屏功能按系统提示授予所需权限。
- 打开顶部应用选项中的“设置”，修改昵称、主机名、分组、聊天记录进入动画和消息提示音。
- 点击“保存并广播”保存设置并刷新上线信息；未发现联系人时可点击“刷新用户”。

## 使用指南

### 会话管理

右键联系人 / 群聊，或打开聊天顶部的“会话管理”菜单：

| 操作 | 行为 |
| --- | --- |
| 置顶 | 固定在置顶区域，离线后仍保留位置 |
| 免打扰 | 保存消息并累计未读，不发送桌面通知；联系人抖动和协助弹窗也不再提醒，群聊中继仍继续 |
| 备注 | 本机显示名称，最多 80 个字符；不修改对方昵称、网络身份或既有消息正文 |
| 标签 | 最多 10 个，每个最多 24 个字符；支持逗号 / 顿号分隔、去重和精确筛选 |
| 屏蔽联系人 | 停止该联系人的新消息、图片、文件与控制提醒，阻止向其发送及中继，取消未完成传输 |
| 屏蔽群聊 | 停止该群的展示、发送与中继，不等于屏蔽全部群成员的普通私聊 |

- 备注、标签、提醒和屏蔽策略保存在本机 SQLite，重启保留；对方上线、改名或聊天记录导入不会覆盖这些设置。
- 屏蔽会清除当前未读，但保留历史、草稿和已完成附件；“仅屏蔽”筛选可找到并解除屏蔽。屏蔽期间未保存的消息不会补收，已发出的消息不能撤回。
- 联系人使用与 IP 解耦的身份关联；能够确认是同一设备时，换 IP 不会丢失这些设置。具体匹配边界见[联系人换 IP](#联系人换-ip)。

### 发送文件与图片

- **文件选择**：点击回形针添加普通文件，确认后点击发送。
- **粘贴**：在输入框使用 `⌘V` 粘贴文本或图片；图片先进入待发送区，可移除后再发送。
- **截屏**：点击截屏按钮进行系统区域截图，完成后回填待发送区。
- **拖拽直发**：选中在线联系人或有在线成员的群聊，将文件 / 图片拖入聊天记录区或输入框，松开后直接发送，不会发送或清空已有草稿。

拖拽单批最多 **50 项**，单张图片最多 **20 MB**，普通文件最多 **2 GB**。同批重复路径只处理一次；保留顺序，连续图片按最多 9 张一组发送，普通文件分别发送。

附件在后台复制到应用目录，不移动源文件。准备期间可取消，切换会话或停止通信也会取消未提交内容；只有 IP 改变且仍识别为同一联系人时可继续发送。部分附件失败时会发送其他有效项并提示错误，目标离线或群成员变化时重新校验。

暂不支持文件夹、符号链接、网络链接及需要先生成文件的拖拽内容；请先保存到本地，文件夹需先压缩。普通文件提交后的取消与重试在下载中心管理。

### 历史消息搜索

- 主工具栏历史按钮或 `⇧⌘F` 搜索全部会话；聊天顶部放大镜或 `⌘F` 默认搜索当前会话。
- 联系人 / 群聊、日期范围、关键词、文本 / 图片 / 文件类型可组合使用；离线联系人也可查询，关键词可留空。
- 日期按本机时区包含起止两天的全天消息；类型依据附件元数据，而不是扩展名猜测。
- 关键词匹配正文或附件名称，不区分英文大小写；特殊字符按普通文本处理。按类型筛选时只查询相应正文 / 附件字段，不搜索 OCR 或文件内部内容。
- 图片结果直接展示缩略图，普通文件支持 Quick Look；“定位到聊天”加载原消息附近上下文并高亮，可继续翻页或回到最新消息。
- 查询完整 SQLite 历史，不受当前会话缓存限制；使用后台查询、防抖和每页 60 条的游标分页。

### 聊天记录导出与导入

主工具栏“更多”菜单提供导出与导入；历史搜索窗口的“导出结果”沿用当前筛选，导出全部匹配记录，而非仅当前页面。

| 格式 | 用途 |
| --- | --- |
| TXT | UTF-8 纯文本，便于查阅与检索 |
| Markdown | 便于文档整理，使用相对路径引用附件 |
| HTML | 浏览器查看，直接展示可用图片，消息内容会转义 |

- 导出文件旁生成 `FeiQ-Attachments-<UUID>` 附件目录；迁移时请一起复制，不会移动原附件。
- 三种格式均附带本应用的结构化恢复数据，保留消息 ID、时间精度与附件信息。**仅支持导入本应用的完整导出记录**，不支持任意第三方 TXT；修改可读正文不会改变恢复数据。
- 导入先预览，再合并写入；同一消息 ID 去重，跨会话 ID 冲突会回滚，不产生新消息通知或新增未读。
- 不覆盖已有联系人、群聊及本机会话策略；新联系人默认为离线，新群聊不恢复成员关系，避免自动启用中继。
- 可用附件复制到本机管理目录。附件丢失时仍可导入元数据，但不能恢复内容；拒绝危险路径、符号链接和大小不符的附件。
- 单个记录文档上限 200 MB、单个附件上限 2 GB；大批量数据建议分联系人或日期导出。覆盖导出文件不会自动删除旧附件目录。

**记录导入是合并，数据库恢复是覆盖；两者均为明文数据，不是加密备份。**

### 历史图片卡片预览

- 点击聊天记录图片进入会话图库：图片直接展示，不添加底板、描边或圆角遮罩；两侧保留相邻缩略图，左右切换带滑动、缩放和轻微透视效果。
- 支持箭头按钮、键盘 `←` / `→`、未放大时横向拖动、点击侧卡切换；首尾不循环。
- 保留双击放大、捏合缩放、放大后拖动、旋转、复制和 Finder 定位；切换图片重置变换。文件缺失时仍可切换其他图片。
- 只挂载当前及前后各一张卡片，相邻图片后台降采样并缓存，不一次解码所有历史原图。开启 macOS“减少动态效果”后不播放卡片滑动动画。
- 同条消息中的多图另有最多 9 张的折叠卡片展示，支持翻页与单张删除；草稿等独立附件预览不混入会话图库。

### 下载中心

点击侧边栏“下载中心”、顶部传输按钮，或按 `⇧⌘J` 打开。关闭面板不影响后台传输。

| 页面 | 内容 |
| --- | --- |
| 接收任务 | 默认页面，集中查看接收进度；批量操作只影响接收方向 |
| 历史附件 | 从 SQLite 查询全部会话的已记录附件，默认接收方向，也可查看发送或全部 |
| 全部传输 | 管理收发任务、状态、错误和传输详情 |

- 历史附件支持联系人、备注、发送者、日期、类型、方向和文件名筛选，每页 60 个附件；图片显示缩略图，支持预览、打开、Finder 定位和跳转原消息。
- 附件落盘、导入、删除和修改备注后自动刷新，也可手动检查文件状态。缺失文件保留元数据，不会自动重新下载。
- 任务展示真实字节进度、速度、剩余时间和错误；“等待对方接收”不代表正在上传，实际写入 TCP 后才累计进度，5 分钟无人接收会失败。
- 默认发送 / 接收各并发 3 个，可调整为各 1–6 个；支持暂停队列、排序、单项 / 批量取消和失败重试。暂停队列不打断已建立的连接。
- “全部传输”的批量操作遵循方向筛选，不受关键词或状态筛选限制。取消会关闭连接并清理接收临时文件，不删除源文件或已完成附件。
- 重试从零开始；接收重试成功补全原消息，不重复增加未读或通知。对方已丢弃发送任务时需重新发送。
- 清理传输记录不删除文件；批量清理保留失败项供重试。切换离线会取消未完成传输并暂停队列。

**历史附件跨重启保存，传输任务队列暂不跨重启恢复，也不支持断点续传。** UDP 内嵌图片沿用分片通道，不纳入 TCP 队列；“发送完成”不等于对方已保存或阅读。

### 消息接收提示音

打开“设置 → 消息提醒 → 消息接收提示音”，可选：**系统默认、玻璃（Glass）、清脆（Ping）、轻响（Pop）、轻铃（Tink）、无提示音**。

- 点击“试听”预听，点击“保存并广播”后生效，重启保留；切换选项或关闭设置会停止自定义试听，取消不改变已保存选项。
- “无提示音”仅关闭声音，不关闭消息与通知横幅；免打扰、屏蔽、当前正在查看会话的提醒规则不变。
- 收信声音通过 macOS 通知系统播放，不额外响铃或绕过系统权限、通知声音开关和专注模式；主动试听除外。
- 自定义选项使用本机系统音效，复制到用户 / 应用容器的 `Library/Sounds/FeiQMac-*.aiff`。准备失败时不保存新选择；运行时不可用则回退系统默认，不支持导入任意音频。

### 联系人换 IP

- 新会话 ID 与 IP 解耦，优先识别飞秋扩展头中的设备标识；无标识时使用可确认的主机信息，不仅凭相同昵称合并联系人。
- 识别为同一设备后继续使用原会话，保留历史、草稿、未读、群成员关系及置顶 / 备注 / 屏蔽等设置。
- 启动时保守归并旧重复会话，保留消息、附件引用与删除标记；合并标签 / 备注超出限制时保留独立会话，不丢弃信息。
- 发现新地址后，文字、图片、群消息及文件排队 / 重试使用最新地址；旧 IP 被其他设备复用不会沿用原会话，旧地址迟到的下线包不会使迁移后的联系人下线。
- 需先收到对方的新地址广播或消息，也可“刷新用户”。设备标识与主机信息同时改变、缺失或存在歧义时，不自动猜测合并。
- 已有 TCP 连接中断可能需要重试，不能无缝迁移正在传输的数据。飞秋设备标识**未经身份认证**，不是安全身份凭据。

### 数据库维护

通过顶部应用选项菜单进入“数据库维护”。

| 操作 | 行为与边界 |
| --- | --- |
| 统计占用 | SQLite / WAL / SHM、图片、文件、安全备份、消息数及缺失 / 无引用附件；共享路径只计一次，逻辑大小不等于 APFS 实际释放量 |
| 清理旧附件 | 按截止日期预览后确认，依据最后一次消息引用判断；保留有新引用的共享文件，可选清理无引用旧文件 |
| 完整备份 | 保存独立 `.feiqbackup` 文件夹，包含数据库一致快照、清单及关联附件，采用相对路径和 SHA-256 校验 |
| 覆盖恢复 | 校验后先自动备份当前数据，再事务式替换记录；失败不覆盖原记录，成功后需重启应用 |

- 查看统计无需离线；清理预览、清理、备份和恢复需暂停通信、结束传输及附件准备，待内嵌图片关联完成或超时。恢复前还需处理未发送草稿，不会自动丢弃草稿或取消任务。
- 清理仅删除本机受管理的附件内容，跳过草稿、本次运行传输使用的文件、链接、子目录和源文件；消息正文及附件元数据保留，清理后无法再打开内容。预览过期会要求重新检查，建议先备份。
- 备份应保存到数据目录之外，完整保留 `Database.sqlite`、`manifest.json`、`Images/` 和 `Files/`。
- 备份包含联系人及设备标识、群聊、消息、未读、会话策略和关联附件；缺失 / 目录外附件只保留元信息，不含无引用文件、草稿、本机昵称、提示音和界面偏好。
- 恢复前的安全备份保存在数据目录的 `Backups/`；恢复保留旧附件，新附件使用独立路径。成功后保持离线并禁止旧缓存写回，**退出并重新打开应用后再使用**。
- 备份未加密；校验仅检查完整性，不能证明来源可信。请只恢复可信备份。

## 数据与安全

默认数据目录为 `~/Documents/飞秋 Mac/`：

```text
飞秋 Mac/
├── ChatHistory.sqlite    # 消息、联系人、群聊、会话策略
├── Images/               # 本机保存的图片
├── Files/                # 本机保存的普通文件
└── Backups/              # 覆盖恢复前自动生成的安全备份
```

- 本机身份、动画和提示音等偏好保存在 UserDefaults；提示音文件位于前述 `Library/Sounds`。
- 数据库使用后台串行队列与分页查询；支持从早期 `ChatHistory.json` 迁移，不因正常重启或重新编译而清空。
- 删除消息 / 图片会清理不再被其他消息引用的受管理副本；数据库维护清理同样不可撤销。重要记录请先备份。
- 应用不主动上传云端，但“文稿”目录可能受用户自己的 iCloud / 备份软件管理，请同时检查系统同步设置。
- UDP/TCP 飞秋兼容通信没有端到端加密，数据库、导出记录与备份也未加密；不要在不可信网络上传输敏感内容。
- **中继群会转发成员发给 Mac 的普通私聊**，切换单聊窗口不能可靠区分这类消息。不要把需要敏感私聊的联系人加入中继群。

## 协议兼容与限制

| 能力 | 实现与验证边界 |
| --- | --- |
| 发现与文字 | IPv4 UDP `2425`、上线 / 离线、消息回执，GB18030/GBK，按选项识别部分 UTF-8 报文 |
| 飞秋扩展头 | 支持 `1_lbt6_0#...` 及部分私有上线命令，用于兼容发现和设备识别 |
| 内嵌图片 | 正文图片 ID + UDP `0x2000C0` 分片、`0xC1` 确认；乱序重组、去重、超时与有限重试 |
| Windows 图片 | 兼容 CORE / V2–V5 位图、RLE、颜色 / 透明掩码、内嵌 JPEG/PNG、zlib/gzip 和长度前缀；实际失败原图仍需重发验证 |
| 普通文件 | UDP 附件清单 + TCP `2425` / `GETFILEDATA`，流式收发与安全落盘；兼容发送端源端口并回退标准端口 |
| 表情 | 96 项飞秋码双向转换，Mac 显示近似 emoji；不复刻 Windows GIF，不保证任意 Unicode / 肤色变体跨端一致 |
| 抖一抖 | UDP `0xD1` 请求 / `0xD2` 回执，3 秒发送间隔，去重并尊重减少动态效果；不向群成员中继 |
| 群聊 | Mac 在线中继，Windows 收到带群名 / 发送人标记的普通消息；非原生群 ID、邀请和成员同步协议 |
| 远程协助 | 识别 `0xB0` 请求并安全提示；尚未实现同意回包、画面传输、键鼠控制与结束通道 |

图片发送统一转换为 JPEG，最长边 4096 像素、质量 0.9；GIF 仅首帧，透明度不保留。图片单张上限 20 MB，普通文件单个上限 2 GB。历史中未成功落盘的图片不能靠升级自动补回，需要发送方重发。

协议参考：[飞秋报文说明](feiqiu-README.md) · [原生群聊实施说明](GROUP_INTEROP.md) · [表情参考码表](https://github.com/zyqg/feiq-android/blob/8314e26cd043e3f83f0fb69b48653d1eb7504203/android/app/src/main/java/com/feiq/droid/net/FeiqEmoticons.kt)。

目前不支持文件夹层级传输、原生语音、Windows 原生群聊或真正的远程控制。不承诺离线送达、跨公网、云端同步、跨客户端撤回、统一已读状态或任意富文本完整还原；这些不是本地界面增强可以补足的协议能力。

## 常见问题

| 问题 | 排查方式 |
| --- | --- |
| 找不到 Windows 联系人 | 检查同一广播域、本地网络权限、双方 UDP `2425` 防火墙，点击刷新；访客 Wi-Fi / VLAN 可能隔离广播 |
| 文字能发但文件失败 | 检查 TCP `2425` 入站规则；保留 `No route to host` / `Connection refused`、附件清单、消息包号等日志 |
| 换 IP 后未关联原会话 | 等待新广播或主动刷新；核对设备标识 / 主机信息是否仍可唯一匹配，不按昵称强行合并 |
| Windows 图片解析失败 | 区分粘贴图片的 UDP 分片与文件发送的 TCP 通道；保留日志中的长度、文件头和位图参数，并请 Windows 重发原图 |
| 中文或表情乱码 | 检查客户端版本与报文编码，优先使用内置飞秋表情面板；任意粘贴的 Unicode 不保证旧客户端兼容 |
| 没有提示音 | 检查已保存的提示音选项、会话免打扰 / 屏蔽、当前会话状态、macOS 通知声音与专注模式；主动试听不等于通知权限已开启 |
| 历史附件显示缺失 | 确认文件未被移动、手动删除或维护清理；元数据仍可查询，应用不会自动重新下载 |
| 构建末尾签名 / DMG 失败 | 检查既有打包脚本的产物路径、证书和 `create-dmg`，不是仅关闭 Xcode 自动签名即可解决 |

网络日志用于定位广播、编码、协议与传输问题，不记录完整失败图片。提交问题时建议提供 macOS / Windows 客户端版本、操作方式和脱敏日志，不公开聊天正文或完整备份。

## 开发与验证

在仓库根目录按需执行；每个脚本都会进行相关回归并检查完整应用源代码类型，不运行项目的签名 / DMG 脚本。

| 命令 | 主要覆盖 |
| --- | --- |
| `bash Tests/run-image-preview-checks.sh` | 图片图库 / 三卡片窗口 / 首尾与快速切换、接收流程、内嵌协议、Windows 图像格式 |
| `bash Tests/run-history-search-checks.sh` | 历史组合查询、分页 / 定位、三种归档往返、缩略图与安全路径 |
| `bash Tests/run-drop-send-checks.sh` | 混合拖拽、分组、草稿保留、取消 / 超时、原生输入框、准备中换 IP |
| `bash Tests/run-conversation-management-checks.sh` | 会话策略持久化、屏蔽收发 / 中继、提醒、设置失败保护 |
| `bash Tests/run-file-transfer-checks.sh` | 进度、并发、暂停 / 排序、取消 / 重试、Socket 读写、端口回退 |
| `bash Tests/run-download-center-checks.sh` | 全局附件检索、附件级分页、跨重启、刷新、原消息定位 |
| `bash Tests/run-peer-identity-checks.sh` | 稳定身份、旧库归并、IP 复用隔离、旧会话延续及最新地址路由 |
| `bash Tests/run-database-maintenance-checks.sh` | 占用、清理保护、一致备份、篡改拒绝、安全恢复 / 回滚与写入锁定 |
| `bash Tests/run-notification-sound-checks.sh` | 选项保存、音效安装 / 修复、静音通知内容，不播放声音或投递通知 |

- 9 个脚本覆盖 15 个独立检查程序，部分公共协议检查会被不同脚本重复运行。
- 使用临时 SQLite / 文件和模拟网络；文件传输检查还使用 `127.0.0.1` TCP 与 Unix socket pair，不广播真实局域网消息，不清理或恢复用户实际数据。
- 拖拽检查需要系统允许临时文件的 NSItemProvider 访问，Socket 检查需要本机监听权限；受限沙盒可能需要额外授权。
- Windows 图片检查含 29 组格式（分别覆盖两种 bitmap 标志）及 16 组异常输入，基于合成样本，不代表覆盖所有 Windows 客户端私有变体。
- 仍需完成 Windows 飞秋 2013 双机图片 / 文件收发、真实 DHCP 切换、Finder 手势、卡片动画交互、通知 / 专注模式声音与签名发行包验收。

## 技术架构

```text
View → ViewModel → Repository → Service / Persistence → Model
```

`ChatViewModel` 管理页面与交互状态，`DefaultChatRepository` 组合消息、附件、群组、会话及通知能力；`FileTransferCenter` 调度传输任务，SQLite 后台队列处理历史查询、迁移与维护。身份匹配与最新地址路由独立于会话 ID，避免 DHCP 变化割裂历史。

```text
FeiQMac/
├── Models/          # 消息、联系人、传输、搜索、归档、会话策略与维护模型
├── Protocol/        # 飞秋报文、编码、内嵌图片与表情
├── Network/         # UDP/TCP、流式传输、取消与网络服务接口
├── Persistence/     # SQLite 表结构、分页查询、迁移和维护入口
├── Services/        # 缩略图、解码、拖拽、传输调度、备份、通知与设置
├── Repositories/    # 业务组合、历史归档、联系人身份与会话设置
├── ViewModels/      # 聊天、搜索、归档、图库、历史附件与维护页面状态
├── Views/           # 聊天、下载中心、卡片预览、设置与维护界面
└── Resources/       # Info.plist 与应用资源
Tests/               # 独立 Swift 检查程序与运行脚本
```
